#Blueberry Farm Site

##システム概要

ブルーベリー農園の営業日管理と情報発信を目的としたwebサイト
経営者は営業日を更新し、その情報を利用者へリアルタイムに公開できる。
AWSのサーバーレスアーキテクチャを採用し、低コストで運用しやすい構成を目指した。

理由：⓵経営者が専門知識を必要とせず、営業日等を迅速に簡単に更新できる仕組みにしたかったため（顧客と経営者でサイトのページを分けたかった）

　　　⓶経営者自身が作成できずコストも出来るだけ低く抑えたい要望があったため

　　　⓷リピーターの方がブログをあげてくれているものの、サイトがなく新規顧客や情報が広がらない

AWS
##1 Amazon S3
役割：静的ファイル（HTML/CSS/JAvascript/画像）の保存に使用

選んだ理由：静的サイトのみ、低コストで管理のしやすさがあるから


##2 Dynamo DB
役割：経営者で設定した営業日カレンダーのデータを保存して、顧客向けサイトに反映するため

選んだ理由：経営者側で更新したデータを効率よく保存・取得し、顧客側へ反映できる構成にしたかったから


##3 AWS Lambda
役割：API Gatewayから呼び出されて営業日データの登録や取得等実行する。

選んだ理由：サーバーレス構成でサーバー管理が不要なため、運用負荷と運用コストが抑えられるから


##4 API Gateway
役割：フロントエンドからのリクエストを受け取り、Lambdaへ連携するAPIとして使用

選んだ理由：サーバーレス構成にし、フロントエンドとバックエンドを安全に繋ぐため


##5 Cloud Front
役割：S3に保存したwebサイトを高速かつ安全に配信

選んだ理由：世界中から高速アクセスで、HTTPS通信にも対応できるため

##6 Route 53
役割：独自ドメインとCloudFrontを紐づける

選んだ理由：独自ドメインでアクセスできるようにし、利用しやすいwebサイトにするため

##7 IAM
役割：AwSサービスのアクセス権限を管理する

選んだ理由：必要最低限の権限を設定し、安全にAWSリソースを運用するため


##工夫した点
-利用者画面と管理者画面をS3バケットで分離

-APIGatewayをGETとPOSTで分割
　
-サーバーレス構成により運用コストを削減

-CloudFront経由で高速配信を利用し、迅速に反映
